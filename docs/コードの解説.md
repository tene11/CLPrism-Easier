# コードの解説

このリポジトリのコードを日本語で説明します。
パッチ本体のコメントは、本家 Prism Launcher に PR を出せるよう英語のままにしています。
このファイルは `patches/` の外にあるので、本家への PR には含まれません。

パッチを変えたときは、このファイルも合わせて直してください。

---

## 全体の流れ

```
PRISM_VERSION のタグの Prism Launcher
        │  apply.ps1（手元）／build-windows.yml（GitHub）
        ▼
patches/*.patch を番号順に git am で当てる
        │  build.ps1（手元）／build-windows.yml（GitHub）
        ▼
Windows 版をビルドして、ポータブル版の zip にする
```

Prism の新しいバージョンが出たときは、`follow-prism.yml` が毎日チェックして、
パッチが当たればプルリクエストを作り、当たらなければ issue を作ります。

---

## フォルダとファイル

| ファイル | 役割 |
|---|---|
| `PRISM_VERSION` | パッチを当てる Prism Launcher のタグ（例: `11.1.1`） |
| `patches/` | Prism Launcher への変更点。1 コミット = 1 ファイル |
| `apply.ps1` | Prism を取得して、パッチを当てる |
| `build.ps1` / `build.bat` | ビルドに必要なもの（VS、Qt、JDK、vcpkg）をそろえてビルドする |
| `update-patches.ps1` | 手元の Prism のコミットから `patches/` を作り直す |
| `publish.ps1` / `publish.bat` | このフォルダを GitHub に push する |
| `scripts/check-prism-update.sh` | Prism の新バージョンにパッチが当たるか試す（CI 用） |
| `scripts/report.sh` | 上の結果をブランチ・PR・issue にする（CI 用） |
| `.github/workflows/build-windows.yml` | GitHub 上で Windows 版をビルドして Releases に置く |
| `.github/workflows/follow-prism.yml` | 毎日 Prism の新バージョンをチェックする |

### スクリプトの注意点

- パッチは改行コードが LF です。Windows の Git は CRLF に変えようとするので、
  `apply.ps1` では `core.autocrlf=false` にしてから取り出し直しています。
- `build.ps1` は、パッチと `PRISM_VERSION` のハッシュを
  `PrismLauncher/.git/cleanroom-patches.sha256` に保存しています。
  ハッシュが変わっていたら、パッチを当て直します。
- `publish.ps1` は、2 回目以降は `gh repo view` で実際の公開先を調べて使います。
  `$RepoName` は、初回にリポジトリを作るときの名前です。

## パッチの中身

追加したファイルは主に `launcher/minecraft/cleanroom/` にあります。

### 0001 バージョン一覧を GitHub Releases から取る

`CleanroomVersionList.cpp/.h`

- Cleanroom は Prism の meta サーバーに無いので、GitHub API
  （`CleanroomMC/Cleanroom/releases`）から一覧を取ります。
- MMC インスタンス zip が付いているリリースだけを一覧に載せます。
  zip の名前は版によって違うので、`cleanroom` を含む `.zip` を探し、`mmc` を含むものを優先します。
- 「種類」の列は、GitHub のプレリリースの印か、タグの `alpha` / `beta` から決めます。
- `ParentVersionRole` に `1.12.2` を返すので、1.12.2 以外のインスタンスでは一覧に出ません。
- テスト: `tests/CleanroomVersionList_test.cpp`

### 0002 ローダー画面に「Cleanroom」タブを足す

`InstallLoaderDialog.cpp`

- 既存の `InstallLoaderPage` を継承した `CleanroomLoaderPage` を作り、
  バージョン一覧だけ Cleanroom 用に差し替えています（`versionList()` を上書き）。
- タブの ID は `cleanroom` です。Cleanroom 自体は `net.minecraftforge` として入るので、
  これはコンポーネントの uid ではありません。

### 0003 選んだバージョンをインストールする

`CleanroomInstallTask.cpp/.h`

インストールは次の順で進みます。

1. zip をダウンロードして展開する（`InstallTask`）
2. 中身を確認する（`readInstancePackage`）
   - `patches/` フォルダがあるか、`net.minecraftforge.json` が入っているか
   - `mmc-pack.json` の順番（LWJGL → Cleanroom）で並べる
3. インスタンスに入れる（`installPackage`）
   - 空の jar（バニラの LWJGL 2 を隠すためのもの）をインスタンスの `libraries/` にコピー
   - 既存の Forge と LWJGL を消して、zip の中のパッチに置き換える

画面側（`InstallLoaderDialog.cpp`）は次のことをします。

- 普通の Forge が入っていたら、置き換える前に確認する（`confirmForgeReplacement`）
- インストール後、自動で選ばれていた Java をリセットし、Cleanroom が使える Java があるか確認する
  （`checkCleanroomJava`）

### 0004 Revert と Remove を Cleanroom ごとまとめて行う

`CleanroomInstallTask.cpp`（`uninstall`）、`VersionPage.cpp`

- Cleanroom は Forge のコンポーネントを置き換えているので、普通の Revert だと
  存在しない Forge のバージョンを探してしまいます。
  → Revert は「おすすめの Forge に戻す」、Remove は「Cleanroom・LWJGL 3・空の jar をまとめて消す」にしました。
- Cleanroom の LWJGL 3 だけを消そうとすると止めます。
- `isCleanroom()` は「uid が `net.minecraftforge`、カスタム、名前が `Cleanroom`」で判定します。

### 0005 ダウンロードとインストールを安全にする

- ダウンロード URL は `https://github.com/CleanroomMC/Cleanroom/releases/download/` で始まるものだけ受け付けます。
- zip の中のコンポーネント名はファイル名になるので、`../` などのパスに使える文字を拒否します（`isSafeUid`）。
- 削除時に消すのは、ライブラリフォルダ直下の `<名前>.jar` だけです。
- テスト: `tests/CleanroomInstall_test.cpp`

### 0006 Cleanroom のロゴを使う

タブのアイコンを Forge のものから Cleanroom のロゴに変えます。

### 0007 LWJGL を Cleanroom のものだけにする

- `org.lwjgl3` が残っていると、Cleanroom の LWJGL 3 と 2 つ混ざって起動時にクラッシュします。
- `findLwjglConflict` が、インストールの前に次のことを調べます。
  - `org.lwjgl3` のコンポーネントがある → 消す
  - 手で書き換えた Minecraft が `org.lwjgl3` を要求している → 確認してから Minecraft を元に戻す
  - それ以外のコンポーネントが要求している → インストールを止める

### 0008 Version 画面からバージョンを変える

- Cleanroom で「バージョン変更」を押すと、Forge ではなく Cleanroom の一覧が出ます。
- 同じバージョンを選ぶと、確認してから入れ直します（壊れたときの修復用）。
- インストール処理は `Cleanroom::installWithDialogs` にまとめ、ローダー画面と共通にしています。

### 0009 途中で失敗したときに警告を出す

- インストールや削除では、複数のコンポーネントを順番に変えます。途中で失敗しても元に戻しません。
- コンポーネントを変え始めたあとに失敗したら、エラーのあとに
  「インスタンスが中途半端な状態で起動できないかもしれません」と表示します（`partlyChanged`）。
- ダウンロードや zip の確認で失敗した場合は、インスタンスは変わっていないので表示しません。

### 0010 翻訳しやすくする

翻訳の考え方は、下の「翻訳（多言語対応）」を見てください。

### 0011 新規作成画面で Cleanroom を選ぶ

`CustomPage.cpp/.h/.ui`、`CleanroomCreationTask.cpp/.h`

- 新規作成画面の「カスタム」ページで、Mod ローダーの選択肢に「Cleanroom」を Forge の次に足しました。
- バージョン一覧は、ローダー画面と同じ `Cleanroom::VersionList`（GitHub Releases）を使います。
  1.12.2 以外を選んでいると一覧は空になり、「Cleanroom は 1.12.2 だけ対応」と表示します。
- 作成は `Cleanroom::CreationTask`（`InstanceCreationTask` を継承）が行います。
  1. `VanillaCreationTask` と同じようにバニラのインスタンスを作る
  2. そこへ `Cleanroom::InstallTask` で Cleanroom を入れる（終わるまで `QEventLoop` で待つ。CurseForge の作成処理と同じやり方）
  3. あとは普通の作成と同じく、ゲームのファイルをダウンロードする
- 新しいインスタンスには Forge も別の LWJGL 3 も無いので、ローダー画面のような確認は出しません。
- Java の確認（`checkCleanroomJava`）はしていません。Java は起動するときに Prism が自動で選びます。
- 作成中に「中止」を押すと、Cleanroom のダウンロードも止めます（`abort()`）。

## 翻訳（多言語対応）

### 本家 Prism Launcher のやり方

- リポジトリには翻訳ファイルを置いていません。
- コードの英語の文字列を `tr("...")` で囲みます。
- 別のリポジトリ（PrismLauncher/Translations）がその文字列を集めます。
  翻訳は [Weblate](https://hosted.weblate.org/projects/prismlauncher/launcher/) で有志が行い、
  ランチャーは起動時に翻訳をダウンロードします。

このパッチも同じやり方です。本家に取り込まれるまでは、英語で表示されます。

### 書くときのルール

| ルール | 例 |
|---|---|
| 画面に出る文字列は必ず `tr()` で囲む | `tr("Replace Forge?")` |
| QObject のクラスの中では `tr()`、それ以外（static 関数など）では `Cleanroom::Tr::tr()` | `Cleanroom::Tr::tr("Revert to Forge")` |
| 文をつなぎ合わせない。1 つの文は 1 つの `tr()` に入れて、変わる部分は `%1` `%2` にする | ✕ `tr("needs ") + v` ／ ○ `tr("needs %1").arg(v)` |
| `" or "` のような断片を翻訳させない | 数字の一覧は `", "` でつなぐ |
| `%1` などの意味が分かりにくいときは、直前に翻訳者向けコメント `//:` を英語で書く | `//: %1 is the Cleanroom version` |

`Cleanroom::Tr` は `CleanroomVersionList.h` にある小さなクラスで、
翻訳の文脈（翻訳者から見たグループ名）を `Cleanroom` にするためのものです。
これがないと `QObject` という文脈になり、どの画面の文か分かりにくくなります。

## パッチを直すときの手順

1. `apply.ps1` で Prism にパッチを当てる（`PrismLauncher/` ができる）
2. `PrismLauncher/` でコードを直してコミットする
   - 既存のパッチを直すなら `git commit --fixup` と `git rebase -i --autosquash`、
     新しいパッチなら普通にコミット
3. `update-patches.ps1` で `patches/` を作り直す
4. このファイル（`docs/コードの解説.md`）も直す
5. `publish.bat` で GitHub に上げる
