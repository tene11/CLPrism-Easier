# 開発の手順（開発者向け）

[Prism Launcher](https://github.com/PrismLauncher/PrismLauncher) の「Mod ローダーのインストール」画面で
[Cleanroom](https://github.com/CleanroomMC/Cleanroom)（Minecraft 1.12.2 向けの Forge 後継ローダー）を
選べるようにするパッチ集です。

Prism Launcher 本体のソースは含まず、`patches/` にある差分だけを置いています。
Cleanroom のバージョン一覧は Prism の meta サーバーではなく、Cleanroom の GitHub Releases から取得します。

コードの仕組みは [docs/コードの解説.md](コードの解説.md) にまとめています。

## できること

- ローダー画面に「Cleanroom」タブが増え、GitHub Releases にあるバージョンから選んでインストールできる
- 普通の Forge が入っているインスタンスでは、置き換える前に確認する
- Cleanroom の LWJGL 3 とは別の LWJGL 3（`org.lwjgl3`）が残っていたら外す。手で書き換えた Minecraft がそれを要求している場合は、確認してから Minecraft を元に戻す（2 つの LWJGL が混ざると起動時にクラッシュするため）
- インストール後、Cleanroom が必要とする Java（25）が使われるよう、自動の Java 選択をやり直す
- Version 画面で Cleanroom を選んで「バージョン変更」を押すと、Cleanroom のバージョン一覧から選び直せる（同じバージョンを入れ直して修復することもできる）
- Version 画面の Revert で通常の Forge に戻り、Remove で Cleanroom・LWJGL 3・空 jar がまとめて消える

ほかのローダー（Fabric、LiteLoader など）との衝突チェックは対応していません。

## 対応バージョン

| 項目 | バージョン |
|---|---|
| Prism Launcher | `PRISM_VERSION` に記載（現在 11.1.1） |
| Cleanroom | GitHub Releases にある MMC インスタンス zip（`cleanroom-<version>.zip`）付きのリリース |

## 使い方（GitHub でビルドしたものを使う）

ふだんはこれだけです。手元にビルド用のツールは要りません。

1. GitHub のこのリポジトリの **Releases** を開き、いちばん新しい zip（`PrismLauncher-<バージョン>-Cleanroom-Windows-x64-….zip`）をダウンロードする
2. 今使っている Prism のフォルダ（ポータブル版の `install` フォルダ）の上に、上書きで展開する
   - インスタンスやアカウントはそのまま引き継がれます
   - 初めてなら、空のフォルダに展開して `prismlauncher.exe` を起動するだけです

パッチを変更して `publish.bat` で GitHub に上げると、GitHub Actions（`build-windows.yml`）が Windows 版をビルドし、
新しい Release を作ります。1 回のビルドには 40〜90 分ほどかかります（初回は依存ライブラリのビルドがあるので長め）。

## Prism Launcher の新バージョンへの追従（手動）

Prism のバージョンは `PRISM_VERSION` で固定しています。新しいリリースが出ても自動では何も起きません。
上げたくなったときだけ、次の手順で手元で当て直します。

1. `dev` から作業用ブランチを作り、`PRISM_VERSION` を新しいタグ（例: `11.2.0`）に書き換える
2. `.\apply.ps1 -Force` を実行する（新しいタグを取得して、`cleanroom` ブランチにパッチを `git am --3way` で当て直します）
3. パッチが当たらなかったら、`PrismLauncher` フォルダでコンフリクトを直して `git add` → `git am --continue` を繰り返す
   （止まったパッチ名と `git am` の出力を Claude に渡すと早い）
4. `build.bat` でビルドし、Cleanroom のインストール・起動を確認する
5. `.\update-patches.ps1` で `patches/` を書き出し直し、`PRISM_VERSION` と一緒にコミットする
6. `dev` へプルリクエストを出してマージする。Releases に置くときは `dev` を `main` にマージする

### GitHub Actions の使用時間の目安

非公開リポジトリの無料枠は月 2,000 分で、Windows の実行時間は 2 倍で数えられます（公開リポジトリは無料）。
Windows 版のビルド 1 回で 80〜180 分ほど（実際の 40〜90 分 × 2）使います。

## 手元でビルドするとき（任意）

パッチを書き換えて試すときなどは、`build.bat` をダブルクリックすると、必要なツール（Visual Studio Build Tools、
Java、Qt、vcpkg）の準備からビルドまでを手元で行います。結果は `PrismLauncher\install` にできます。

`build.bat` は最初に GitHub から最新のパッチを取り込み、`PRISM_VERSION` かパッチが変わっていれば自動で当て直します。

手動で行う場合の手順:

```powershell
# 1. 本家を取得してパッチを当てる（PrismLauncher フォルダができます）
.\apply.ps1

# 2. 「x64 Native Tools Command Prompt for VS 2022」でビルドする
cd PrismLauncher
cmake --preset windows_msvc -D CMAKE_PREFIX_PATH="C:\Qt\6.10.2\msvc2022_64"
cmake --build --preset windows_msvc --config Release
cmake --install build --config Release
cmake --install build --config Release --component portable
```

`apply.ps1` は既に `PrismLauncher` フォルダがあれば clone をスキップします。
作業用ブランチ `cleanroom` を作り直したいときは `.\apply.ps1 -Force` を使います（そのブランチの変更は消えます）。

### パッチを更新するとき

`PrismLauncher` フォルダの `cleanroom` ブランチで変更をコミットしてから、`.\update-patches.ps1` を実行します。
`PRISM_VERSION` のタグから HEAD までのコミットが、1 コミット = 1 ファイルで `patches/` に書き出されます。
そのあと `publish.bat` で GitHub に上げると、Windows 版がビルドされて Release ができます。

## GitHub に公開・更新するとき

`publish.bat` をダブルクリックします。初回は GitHub へのログイン（ブラウザ）のあと、非公開リポジトリ `prism-cleanroom` を作って公開します。
2 回目以降は、変更をコミットして push するだけです。コミットには GitHub の noreply アドレスが使われます。

## ファイル構成

| パス | 内容 |
|---|---|
| `patches/` | Prism Launcher への変更（`git format-patch` 形式） |
| `PRISM_VERSION` | パッチの対象になる Prism Launcher のタグ |
| `.github/workflows/build-windows.yml` | パッチを当てた Windows 版をビルドし、Release を作る |
| `publish.bat` / `publish.ps1` | このフォルダを GitHub の非公開リポジトリに公開・更新する |
| `build.bat` / `build.ps1` | 必要なツールの準備から手元でのビルドまでを一括で行う |
| `apply.ps1` | 本家の取得とパッチ適用 |
| `update-patches.ps1` | 作業ブランチからパッチを書き出し直す |
| `.gitattributes` | パッチなどの改行コードが Windows で変換されないようにする設定 |
